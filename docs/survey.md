## 1. 언어 — 일본어 모드가 산다

USA 디스크인데도 **JP 텍스트·전각 폰트가 전부 실려 있고**, 사용자가 실기에서
**일본어로 나오는 것을 확인했다**. 그래서 한글화는 Conker Xbox 와 같은 전략을 쓴다:
**일본어 경로(전각 2바이트)를 한글로 갈아끼운다.**

근거 보강: `default.xbe` 안에 `MessageEvent\MesData_Stage01_JP.msg` 같은
**`_JP` 경로만** 있고 `_EN` 문자열은 없다 → 일본어가 기준 문자열이고 런타임에
바꿔치기하는 구조다.

영어는 반각(`Arial_h_tbl.bin` + `font_hs_test_arial.txb`) 경로로 그린다.

## 2. 텍스트 — 무압축 평문

| 위치 | 개수 | 내용 |
|---|---|---|
| `messageevent/*.msg` | 46 (EN/JP 쌍) | 스테이지 무전·자막 |
| `menudata/TextData/*.msg` | 18 (EN/JP 쌍) | 메뉴 설명, 판도라의 상자(도감), 서브시나리오, 영상, 오프닝 |
| `menudata/*.mnu` | 3 | 도감 분류 (creature / empire / world) |

문자열은 **NUL 종단, 4바이트 정렬**, JP 는 cp932(Shift-JIS), EN 은 ASCII.
개행은 `\n`(0x0A). 인라인 토큰 `$c5` `$c7` 같은 색상 지정자가 있다(Tutorial 등).

분량 (`tools/msgfile.py` 스캐너 기준):

| | 문자열 | 글자 | 슬랙(널패딩) |
|---|---|---|---|
| EN | 1,779 | 144,430 | 35,882 B |
| JP | 1,502 | 41,784 | 29,551 B |

JP 고유문자 **1,488자** (가나 151 / 한자 1,214 / 기타 123).

### 레코드 문법 — ★미확정
```
u32 ID + 0x24 헤더 → 줄엔트리 0x18 + 문자열 + 4바이트 정렬 패딩
```
Stage/도감 계열은 이 구조로 맞는데 **Tutorial 은 줄엔트리 길이가 다르다**
(0x2C 로 보이는 자리가 있다). 헤더 안의 값 대부분은 런타임 포인터(0x14xxxx,
0xdfxxxx 대)로 보이며 실행 중 채워지는 자리 같다.
→ 지금은 **바이트 스캔으로 문자열과 오프셋만** 잡는다(`tools/msgfile.py`).
   제자리 덮어쓰기에는 이걸로 충분하고, 길이를 바꾸려면 문법을 마저 풀어야 한다.

파일이 2048 배수로 패딩돼 있어 슬랙이 있지만, ★**Conker Xbox 는 파일 크기를
바꾸면 부팅불가였다**([[feedback_kr_batch_file_encoding]] 아님 —
`project_conker_xbox_kr` 의 하드 룰). Orta 도 같은 제약인지 **미확인**이므로
기본 방침은 **원본과 같은 크기 유지**로 잡는다.

## 3. 폰트 — 장면별 아틀라스 + 직접 매핑표 ★★

`sprite/Font/` 에 **장면마다 한 벌씩** 있다.

```
Zenkaku_<장면>.txb        아틀라스 (PCMP 압축 → TXRB → DXT3)
Reisyo_<장면>_z_tbl.bin   SJIS → 글리프 인덱스 표
Zenkaku_Common.txb        공용(가나·기호). 모든 장면이 같이 쓴다
Reisyo_Cmn_z_tbl_cmn.bin
font_hs_test_arial.txb    반각 라틴
Arial_h_tbl.bin
```

장면: `Stage1`~`Stage10`, `Menu`, `Movie`, `OpeningDemo`, `Tutorial`,
`Mission01`~`05`, `SubScenario01`~`07`.

### 3.1 z_tbl — ★해시가 아니라 직접 표
```
0x00 u32 zenkaku    1 = 2바이트, 0 = 1바이트
0x04 u32 pages      아틀라스 페이지 수 (Menu 만 4, 나머지 1)
0x08 u32 glyph_w    28
0x0c u32 glyph_h    28
0x10 u32 atlas_w    512
0x14 u16 * 9024     코드 → 글리프 인덱스, 0xFFFF = 없음
                    인덱스 = 리드순번*192 + (트레일 - 0x40)
                    리드 47개 = 0x81..0x9F, 0xE0..0xEF
     (반각은 u16 * 256, 인덱스 = 바이트값)
이후 0 패딩 (파일 18432 B / 2048 B)
```
**Conker 에서 못 풀었던 charmap 해시 문제가 여기엔 없다.** 아무 SJIS 코드나
원하는 글리프 칸에 붙일 수 있다.

⚠️표에는 **센티널**이 섞여 있다. 미수록 구역(NEC/IBM 중복한자 등)이 통째로
한 값(7182 / 7196 등)을 가리킨다. **진짜 글리프 수는 아틀라스에서 실측**해야 한다
(`tools/cells.py`). 「값의 개수」나 「최대 인덱스」로 세면 틀린다 — 둘 다 틀렸었다.

### 3.2 아틀라스 — PCMP → TXRB → DXT3
```
PCMP  0x00 'PCMP' / 0x10 u32 blobs=1 / 0x14 u32 해제크기 / 0x18 u32 압축크기 / 0x20~ LZSS
TXRB  0x00 'TXRB' / 0x04 u32 pages / 0x14 u32 0x200(용도불명) / 0x18 u16 0x0106
      페이지 데이터 시작 = pages==1 이면 0x20, Menu(4페이지)는 0x50
      페이지당 262,144 B = 512×512 **DXT3(BC2)**
```
- ★★**글자는 알파 채널에도, 컬러 채널에도 있다.** 게임은 컬러 × 알파로 그린다.
  ⛔세션1 에 여기 「컬러 절반은 대개 단색」이라고 적어둔 것은 **틀렸다.** 컬러를
  디코드하면 `々圧意遺育運栄奥…` 가 또렷이 읽히고, 글자 칸의 컬러 비단색 픽셀이
  알파 잉크보다 **오히려 많다**(人 칸: 컬러 166 vs 알파 118).
  세션2 에서 이걸 믿고 알파만 갈아끼웠다가 실기에 «깨진 조각»이 나왔다 —
  화면에 남은 건 **내 한글(알파) ∩ 원본 한자(컬러)** 의 교집합이었다.
  → 지문·교훈은 [[feedback_dxt_color_channel_also_has_glyph]]
- 컬러 블록 실측: 글자 있는 블록은 **c0=0xFFFF(흰) / c1=0x0000(검)** 계열
  (215종 중 최빈), `c0 > c1` 이라 DXT1 **4색 모드**. 팔레트 = 255 / 0 / 170 / 85.
  → 쓰기는 `tools/atlaswrite.py` `Atlas.set_cell()` 이 알파·컬러를 **둘 다** 쓴다.
- 셀 **28×28**, 가로 **18칸**, 세로 18줄 → **페이지당 324칸**.
- 스위즐 없음(블록 선형). Xbox 는 압축 텍스처를 스위즐하지 않는다.

검산: 반각 Arial 아틀라스를 풀어 그리면
`! " # $ % & ' ( ) * + , - . / 0 1 …` 가 **그대로 읽힌다**. 잉크 있는 칸 94개 +
빈칸(0x20 스페이스) = **95 글리프**, `Arial_h_tbl.bin` 의 매핑 문자 수 **95** 와 정확히 일치.

## 4. PCMP 압축 — 해독 완료

`.txb` 142 / `.ees` 33 / `.rsb` 25 = **총 200개**가 PCMP. 나머지 `.txb` 385개는
무압축 `TXRB` 다.

LZSS 문법:
- 플래그 바이트를 **MSB 부터** 소비. `0` = 리터럴 1바이트, `1` = 매치 2바이트
- `off = ((b0 >> 4) | (b1 << 4)) + 1`, `len = (b0 & 0x0F) + 3` (최대 18)
- ★★`off` 가 지금까지 낸 출력보다 크면 **0을 채운다**(윈도가 0으로 초기화된 셈).
  이 처리가 없으면 파일 첫 매치에서 바로 터진다 — 여기서 한참 막혔다.
- ★★디코더가 **8번째 토큰의 데이터를 읽기 전에 다음 플래그 바이트를 먼저** 집어간다.
  스트림 = `F0 d0..d6 | F1 | d7 | d8..d14 | F2 | d15 | …`
  인코더를 쓸 때 이걸 놓치면 즉시 깨진다.

검증: **PCMP 200개 전부 해제 성공, 크기 헤더값과 정확히 일치.**
왕복(해제→내 인코더→재해제)도 표본 4개 일치, 압축률 98.6~100.5%.

출처: [reshax.com/topic/17944](https://reshax.com/topic/17944-help-analyzing-panzer-dragoon-orta-xbox-txb-file-format/) (Rabatini).
⛔Xbox 표준 코덱이 아니다 — 검색으로 나오는 `XMemCompress`/LZX·`xbcompress` 는
Xbox 360·GDK 시대이고 매직(`AFCWGPSM`, `0F F5 12 EE`)도 구조도 다르다.

  `pdbox_*` (판도라의 상자 UI), `sprite/PandoraBox/*`. 로고·버튼·크레딧 등.

  `PD1.xbe`(8.5 MB)가 그 실행체. 별건으로 봐야 한다.
- `sprite/name_entry.txb` (729 KB, 16페이지) — 이름 입력 화면.
  Azel 때처럼 「그림에 구운 글자」일 가능성이 있다.
- `.ees` (이벤트 스크립트?) 안에 텍스트가 있는지.
- `movie/*.sfd` 자막이 영상에 구워져 있는지.

## 6. 미확인 리스크

1. **파일 크기를 바꿔도 되는가.** Conker Xbox 는 바꾸면 부팅불가였다. 실기로 확인 전까지
   원본과 같은 크기를 유지한다.
2. **아틀라스 페이지를 늘릴 수 있는가** (Menu 예산이 모자랄 때의 탈출구).
3. 줄 폭·글자 수 상한 — 실기 스샷으로 실측해야 한다.
   ★예산은 **바이트**와 **화면 폭** 두 종류다.
